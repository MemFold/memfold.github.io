MemFold:Learning Compact Soft Memory for Long-Context Personalization via On-Policy Optimization

Small memory. Personal answers.

A useful memory should change what an assistant says. We train a reader to turn a compact representation of a user’s history into answers that put that history to use.

01 / THE IDEA

Remembering is only half the job.

Over many conversations, a user reveals preferences, revises plans, and adds constraints. An assistant needs to decide which details matter now and use them in its answer.

Keeping everything as text makes the reader’s input grow with the history. Compressing that history into a small set of vectors gives the reader a fixed memory budget. But learning to reconstruct text or imitate an answer does not directly teach it how to use memory on the responses it generates itself.

Train memory use by the behavior it supports.

MemFold connects a compact memory interface to on-policy learning. The reader generates its own responses, receives feedback on task outcomes, and gets token-level guidance from a frozen teacher that sees the textual memory.

The budget is at the reader. The reader receives a fixed number of memory vectors. Constructing the memory still requires reading the history; a fixed interface does not make the entire pipeline constant-cost.
02 / HOW IT WORKS

Fold the history.
Learn to read the fold.

A query-conditioned writer extracts relevant information from the interaction history. A Perceiver-style compressor maps this textual memory into K continuous vectors. The reader answers from the query and those vectors.

After supervised initialization makes this interface readable, the on-policy training procedure in Fig. 1 combines two signals on the same student-generated responses:

  1. Reward the outcome. Group-relative policy optimization (GRPO) uses task rewards to improve the reader’s responses.
  2. Guide individual tokens. A frozen textual-memory teacher re-scores the student’s sampled tokens. A detached confidence gate weights this on-policy distillation signal.

The teacher does not generate a separate answer, so it adds scoring passes but no autoregressive decoding. At inference, the teacher is removed. The writer constructs the textual memory, the compressor folds it into vectors, and the reader answers.

03 / THE RESULTS

A small interface.
A stronger long-context reader.

Transfer beyond the training dataset

PrefEval uses checkpoints trained on PersonaMem-32K; LongMemEval uses checkpoints trained and selected on LoCoMo. Neither transfer setting uses target-dataset training. These evaluations test both personalization and broader memory capabilities, including multi-session reasoning and knowledge updates.

Accuracy and cost tell different stories. Aggregate token-equivalent cost is lower than Full Text across all three backbones, but savings are not universal: memory construction costs more on short-history PrefEval, and some individual settings use more tokens.

04 / LEARNING EFFICIENTLY

More from the reader’s own rollouts.

Fig. 2 compares training with Qwen2.5-3B-Instruct on PersonaMem-32K. MemFold improves accuracy more rapidly with optimizer updates and reaches comparable accuracy with fewer student rollouts.

Where does the improvement come from?

In the component ablation, GRPO contributes most of the task gain. Adding OPD improves mean accuracy from 71.9 to 75.4 on PersonaMem-32K and from 86.9 to 87.9 on PersonaMem-128K. Reader initialization is also essential: the reader must first learn to consume soft memory.

The ablation uses 16 sampled responses at temperature 1.0. Its mean accuracy is a different evaluation setting from the main results above. Total training cost also includes initialization and teacher forward passes.

05 / INSIDE THE MEMORY

Does the model actually use it?

Fig. 3B tests memory use by changing the memory at inference. When we replace the correct instance’s memory with shuffled or null memory, accuracy drops substantially on both PersonaMem settings. The reader depends on the memory built for that particular instance.

The budget sweep in Fig. 3A peaks at 256 vectors on both PersonaMem settings. Increasing the budget to 512 does not improve accuracy under the tested training recipe.

What does the memory budget cost?

Fig. 4 shows that changing the number of soft vectors from 64 to 512 has little effect on end-to-end token cost in the tested Qwen3-4B configuration. On PersonaMem-128K, the variation is less than one percent. Reading the history to construct textual memory still dominates the cost.

The textual-memory teacher also scores below the final student on task accuracy. Its role is a bounded token-level reference, not an accuracy oracle. These interventions establish that the memory matters; they do not identify exactly which facts or temporal updates each vector represents.

06 / A PERSONAL ANSWER

The difference is in the details.

An answer can be sensible in general and still be wrong for a particular user. In the PrefEval example in Fig. 6, the interaction history implies a dislike of wearable technology. The model is asked how to monitor fitness progress.

A PrefEval implicit-persona example with Qwen3-4B. The displayed preference summarizes the interaction history and is not given explicitly to the models. This single example illustrates a failure mode, not its frequency or end-to-end efficiency.

07 / TAKEAWAYS

Compact memory, trained for use.

MemFold combines a fixed soft-memory interface with training on the reader’s own behavior. Task rewards drive answer quality; a frozen textual-memory teacher supplies complementary token-level guidance. The result is a compact interface that remains useful across the tested long-context and transfer settings.

There is more to understand: how individual facts survive compression, how readers resolve changing preferences, and how to reduce the cost of constructing memory from long histories. The current evidence is a step toward memory that an assistant can actually put to work.
